1 · The Locked Spec (what we are building)

Project: CMIS — Conversational Memory Intelligence System. Design source of truth: ../cmis-memory/remex_ai_system_design_v1.md (system design v1 + sprint plan + threat model + API contracts + ADRs 0001–0006).

Cognitive job: Decide which parts of a conversation are worth remembering, store them durably with provenance, and return the smallest ranked set of memories that makes the next turn better — without ever becoming the bottleneck it exists to solve. This is explicitly not a bigger-context-window strategy: selective admission, typed storage, ranked retrieval and active decay replace "just put everything in the window."

Inputs: conversation turns (user + assistant text) with metadata (tenant_id, user_id, turn_id, timestamp, source surface); an optional explicit "remember this" signal; on the read side a retrieval query + token budget  →  Outputs: (write) an admit / reject / update-existing decision plus a stored typed memory record carrying source turn, importance and the judge's decision trace; (read) a ranked, token-budgeted memory block with per-item provenance and a degraded flag.

Autonomy level: supervised autonomy — the Write Gate decides admission, and decay/reflection run unattended, but only inside the memory store, only within policy, and every decision is reversible and auditable. The system never takes an action outside its own store.  |  Human-in-the-loop points: user/operator correction (PATCH) and deletion (DELETE) as first-class endpoints; the audit endpoint answering "why do you know this?"; procedural-memory admissions flagged for a secondary check (higher blast radius); decay-curve and ranking weights are tuned against eval reports and reviewed by a human, never auto-shipped.

Failure tolerance: the read path fails open — retrieval degrades to an empty memory set and the conversation continues unpersonalized; it must never return 5xx or block a response. The write path fails closed — no partial writes, and a failed PII check rejects the whole candidate. Provider outage or rate-limit exhaustion parks candidates in a bounded queue (429 backpressure) rather than dropping them. All degradation must be observable.  |  Trust boundary: host app → API is the auth boundary (authenticated tenant_id + user_id on every call); tenant↔tenant isolation is enforced by Postgres row-level security, not application code; the riskiest boundary is worker → external free-tier LLM provider (NVIDIA NIM / Gemini), the one point where conversation content leaves the self-hosted perimeter — so the PII filter runs pre-send, not just pre-store. The memory store is itself an injection-persistence surface (procedural-memory poisoning), so admission must distinguish "the user stated a preference" from "the turn contains an imperative sentence."

G0 diagnostic (5 questions, agentic-swe-master): Q1 Scope — new build (greenfield repo).   Q2 AI components — yes: LLM-judge Write Gate, local embeddings, reflection agent.   Q3 Distributed — yes: API + worker + Postgres + Redis across process/network boundaries with an async queue.   Q4 Trust boundary — yes: multi-tenant data, PII, external untrusted LLM providers.   Q5 Current phase — Phase 0 (Cognitive Design), entering Phase 13/3 for M1 and Phase 14/11 for M2.
Route: New + AI + Distributed + Trust → start at Phase 0 and walk all 20 phases in order.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Copied verbatim from the agentic-swe-master phase "Gate:" lines for every phase this project passes through. A milestone is DONE only when the gates for its phase — plus the always-on gates at the bottom — are checked by the verifier.

Phase 0 · Cognitive Design — Cognitive job is written down. Autonomy level is explicit. Failure modes listed.
Phase 1 · System Architecture — Architecture style chosen with justification. Service graph exists. Boundary types stated (source / deployment / process / service). No cycles in dependency graph.
Phase 3 · Backend & API Layer — Service modules defined. At least one state machine drawn with explicit states. Every outbound call has a timeout strategy. (CMIS: the memory lifecycle capture→admit/reject/update→store→decay→reflect→archive/delete is that state machine)
Phase 4 · Workflow Orchestration — Orchestration topology matches task structure. Workflow states are explicit. Checkpointing strategy defined. Span-of-control ≤ 7 workers per orchestrator.
Phase 5 · LLM & Reasoning Layer — Model routing table defined. All outputs validated against schema. Context budget explicitly managed. Prompt versioning strategy in place. (CMIS: NIM / Gemini free tier → local fallback, and the judge's verdict is schema-validated)
Phase 6 · Memory Architecture — Memory tiers separated explicitly. RAG pipeline uses hybrid retrieval. Every response cites its source. Freshness strategy defined.
Phase 9 · Evaluation Systems — Golden dataset exists. 3-level eval plan written (component / integration / production). LLM-as-judge calibrated. Regression suite runs on every deploy.
Phase 10 · Observability & Tracing — Every agent span captures latency + token count + tool result + cost. Alerts on p99 latency, error rate, and cost drift. Prompt traces searchable.
Phase 11 · Security Architecture — Threat model exists with specific adversary categories. Prompt injection mitigated with instruction hierarchy and sanitization. RBAC implemented. Audit trails are append-only and tamper-evident.
Phase 12 · Reliability Engineering — Every outbound call has circuit breaker + timeout + retry with idempotency. Checkpointing strategy allows resumption after crash. No operation has side effects on retry that it didn't have on first execution.
Phase 13 · Infrastructure & Deployment — All services containerized. Queue strategy chosen. Model serving decision made. Semantic caching reduces token spend on repeat queries.
Phase 14 · Data Engineering — Pipelines are idempotent and rerunnable. Schema changes are backward-compatible for at least one full deployment cycle. Knowledge graph exists if reasoning requires entity relationships.
Phase 15 · Governance & Compliance — Audit trail covers every agent action. Compliance requirements mapped to specific controls. Explainability mechanism exists for user-facing decisions.
Phase 19 · Human-in-the-Loop — Every high-stakes action has an approval gate. Confidence threshold for escalation is defined and tested. Feedback mechanism routes corrections to eval system.
Phase 20 · Continuous Learning — Reflection and learning are separate pipelines. Convergence threshold is explicit. No learning update ships without regression suite passing.

Project-specific success criteria (CMIS)

Read path fails open: GET /v1/memories:retrieve returns 200 {"memories":[],"degraded":true} on internal failure — never 5xx, never blocking.
Write path fails closed: no partial writes; a failed PII check rejects the whole candidate.
PII filter runs pre-send — no candidate text reaches an external provider before a verdict exists.
Tenant isolation is DB-enforced (RLS on every memory-bearing table), proven by a cross-tenant read test.
Every stored fact is attributable (source turn + actor + timestamp) and every judge decision is replayable from its trace.
A user/operator can see, correct, and delete any stored memory; the deletion event survives the deleted content.
Retrieval quality is measured, not asserted: each retrieval milestone beats the recorded evals/reports/baseline.json.
Latency budget holds: read path < 150ms p95 (local only); admission < 30s p95 async, off the user-facing path.

Always-on gates (every milestone, no exceptions)

Dependency direction inward, zero cycles (modular-architecture gate)
Every outbound call has a timeout / circuit-breaker (production-readiness gate)
All LLM/structured outputs validated against a schema (llmops gate)
