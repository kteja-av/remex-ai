Background

Where M3 left off

M3 shipped a working read/write loop: POST stores a memory with a local embedding; GET /v1/memories:retrieve encodes the query, runs pgvector similarity search, and returns the top-k hits with scores. That path assumed every dependency would succeed.

M4 hardens the read path for production reliability. Two system-design invariants drive the work:

Invariant Rule
read_path_fails_open Retrieve never returns HTTP 5xx. Any internal failure yields HTTP 200 with {"memories": [], "degraded": true}.
read_path_makes_no_external_calls Nothing on the retrieve path may import worker LLM providers or call the network. Embeddings and budgeting stay local.
Fail-open: Memory is optional context for the host application. If retrieval fails, the host still gets a normal HTTP response and can answer the user without memories. Contrast with the write path, where a missing encoder should fail loudly — storing text without an embedding creates unsearchable rows.

New responsibilities in M4

Beyond degradation, M4 adds token budgeting and citation plumbing:

  • Token budget — Clients pass token_budget (default 512). The API packs ranked hits until the budget is exhausted and reports token_count.
  • Head/tail placement — After packing, memories are reordered so the best hit sits at the head and the second-best at the tail, mitigating LLM lost-in-the-middle attention bias.
  • Citations — Each returned memory still carries source_turn_ids (provenance from M2/M3), so downstream prompts can attribute facts to conversation turns.
FastAPI dependency order: Dependencies such as Depends(get_encoder) are resolved before the route handler body runs. A try/except inside the handler cannot catch exceptions raised during dependency injection — a subtle trap that M4's L4 verification caught as defect D1.

Intuition

Fail-open vs fail-closed

Before (M3)

Postgres down → 500. Encoder load fails → 500. Any unhandled exception → 500.

The host app must special-case retrieval errors or risk user-facing failures.

After (M4)

Any failure → HTTP 200, memories: [], degraded: true, token_count: 0.

The host treats empty memories as "no extra context" and continues.

Token budgeting toy example

Suppose token_budget = 20 and three ranked memories (best first):

RankContentEst. tokensRunning totalKept?
0"Alpha backend language"66Yes
1"Beta scripting tasks"511Yes
2"Gamma analytics DB"516Yes
3"Delta cloud provider"622 > 20No — greedy break

pack_into_budget keeps the rank-0 prefix while cumulative cost fits. It stops at the first item that would exceed the budget (rank 3 here), so three memories are packed.

Head/tail on four items [r0, r1, r2, r3]: Even indices fill from the left, odd indices from the right → [r0, r2, r3, r1]. Best at head, second-best at tail, weaker items in the middle.

Why pack before place?

Packing assumes the list is still sorted by retrieval rank. place_head_tail permutes items without changing total token cost. If you placed first, the greedy packer would see a shuffled order and might drop high-ranked items that moved to the tail — breaking the rank-prefix guarantee.

The dependency escape (D1)

FastAPI calls solve_dependencies before your handler. With M3's Depends(get_encoder), a model-load failure in LocalEncoder.__init__ raised during dependency resolution — outside the handler's try/except. Combined with @lru_cache on get_encoder (which does not cache exceptions), every request retried the failing load and returned 500 indefinitely.

M4 introduces get_encoder_or_none(): catch load failures in the dependency itself, return None, and let the handler return degraded. The write route keeps strict get_encoder.

Code

1. Token budgeter

File: app/context/budgeter.py (new in M4)

Local token estimate — no external tokenizer:

def estimate_tokens(text: str) -> int:
    stripped = text.strip()
    if not stripped:
        return 0
    return max(1, (len(stripped) + 3) // 4)  # ~4 chars/token

Greedy rank-prefix packing:

def pack_into_budget(items, token_budget: int) -> list:
    if token_budget <= 0:
        return []
    packed, used = [], 0
    for item in items:
        cost = estimate_tokens(item.content)
        if packed and used + cost > token_budget:
            break
        if not packed and cost > token_budget:
            break
        packed.append(item)
        used += cost
    return packed

Head/tail placement (lines 34–48): even indices go left-to-right, odd indices right-to-left into a fixed-size buffer, then compacted.

2. Fail-open retrieve route

File: app/api/routes_retrieve.py

Response model gains token_count and degraded:

class RetrieveResponse(BaseModel):
    memories: list[RetrievedMemory]
    token_count: int = 0
    degraded: bool = False

Safe encoder dependency (lines 44–56):

def get_encoder_or_none() -> Encoder | None:
    try:
        return get_encoder()
    except Exception:
        logger.exception("encoder unavailable; retrieve degrading")
        return None

Handler pipeline (lines 59–96):

@router.get("/memories:retrieve", response_model=RetrieveResponse)
def retrieve_memories(
  query: ...,
  identity: ...,
  encoder: Annotated[Encoder | None, Depends(get_encoder_or_none)],
  limit: ... = 5,
  token_budget: Annotated[int, Query(ge=1, le=100_000)] = 512,
) -> RetrieveResponse:
    try:
        if encoder is None:
            return _degraded_response()
        hits = retrieve_similar(...)
        retrieved = [RetrievedMemory(...) for hit in hits]
        packed = pack_into_budget(retrieved, token_budget)
        placed = place_head_tail(packed)
        return RetrieveResponse(
            memories=placed,
            token_count=total_token_count(placed),
            degraded=False,
        )
    except Exception:
        logger.exception("retrieve degraded", exc_info=True)
        return _degraded_response()
Citations: RetrievedMemory still includes source_turn_ids copied from each MemoryRecord. M4 does not invent new citation fields — it preserves provenance through the pack/place steps because those functions only reorder, never strip fields.

3. Write path unchanged (intentionally strict)

File: app/api/routes_memories.py

POST still uses Depends(get_encoder). A load failure on write returns an error — better than persisting a memory that retrieval can never find.

def test_retrieve_returns_degraded_when_encoder_load_fails(...):
    monkeypatch.setattr(
        "app.api.routes_retrieve.get_encoder",
        MagicMock(side_effect=RuntimeError("model artifacts missing")),
    )
