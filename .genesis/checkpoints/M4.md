## Quiz-me (L4 gate)

**Q1 — Token budgeting order invariant.** `pack_into_budget` runs before `place_head_tail`. Why does order matter, and what breaks if you swap them?
- **Answer:** Packing is rank-prefix greedy (breaks at first non-fitting item), which only works while the sequence is monotonically ranked. After head/tail interleaving the ranking is a permutation, so breaking early would discard higher-ranked items now at the tail. Placement is pure permutation and never changes total cost, so `token_count ≤ token_budget` is guaranteed by construction.

**Q2 — Fail-open escape path.** The route body was already wrapped in try/except, yet pre-fix code returned 500 on model load failure. Where did the exception escape, and why does `@lru_cache` compound it?
- **Answer:** Escaped in `solve_dependencies`, which FastAPI runs before the handler — try/except was downstream of the failure. `@lru_cache` does not memoize exceptions, so every subsequent request retries the load and raises again, causing indefinite 500s rather than one graceful degrade. Model loads lazily on first request (no lifespan hook), so the failure surfaces to a user rather than a health check.

**Q3 — Head/tail slot filling.** For ranked input `r0..r4`, what does `place_head_tail` emit, and prove no slot is written twice?
- **Answer:** `[r0, r2, r4, r3, r1]` — even indices fill left-to-right (3 times, positions 0–2), odd indices fill right-to-left (2 times, positions 4–3). Left pointer ends at 3, right at 2, pointers meet without crossing; every slot written exactly once. Best item at head, second-best at tail, weakest in dead center (mitigating *Lost in the Middle*).
