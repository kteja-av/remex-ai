## L3 Research · local embedding model choice

- sources: official `sentence-transformers/all-MiniLM-L6-v2` model card; official Sentence
  Transformers semantic-search docs; pgvector README.
- decision: use `sentence-transformers/all-MiniLM-L6-v2`, pinned through
  `sentence-transformers==5.6.1`. It is local, compact, intended for sentence/short-paragraph semantic
  search, and emits 384 dimensions matching the existing schema. Normalize document and query
  embeddings. Use pgvector cosine distance (`<=>`) with an HNSW `vector_cosine_ops` index.
- rejected for this baseline: a larger encoder (higher CPU/RAM and latency without measured need),
  external embedding APIs (violates local-only read constraint), and hybrid signals (reserved for M7).

## Quiz-me gate · Q+A

- Q1 (design): `precision_at_k` is micro precision over every returned item rather than mean
  per-query precision with a fixed denominator. What behavior does that price in for M7?
- A1: it charges the retriever for every false-positive item it actually emits, including results
  returned for no-answer queries. M7 can improve by ranking relevant memories above distractors and
  abstaining below a justified threshold; returning fewer arbitrary items is no longer treated as
  equivalent to always filling `k`.
- Q2 (edge): after a pooled connection commits and clears `app.current_tenant`, what does the RLS
  predicate evaluate to and what does retrieval return?
- A2: the transaction-local GUC resets to an empty/missing value. `nullif(current_setting(..., true),
  '')::uuid` becomes `NULL`; `tenant_id = NULL` evaluates to unknown, which the RLS policy rejects.
  Retrieval therefore returns zero rows rather than leaking another tenant's data.
- Q3 (change impact): when M5 adds the Write Gate, what must change in `evals/run.py` for precision
  to move off 0.500, and why can `compute_metrics` remain unchanged?
- A3: the M5 eval must run each labeled candidate through the Write Gate, persist only admitted
  candidates, and pass those actual admitted labels into `compute_metrics`. The metric function is
  already parameterized by `admitted` and `should_admit`, so its arithmetic does not change; keeping
  the same dataset id makes the report comparable to M3's frozen baseline.
